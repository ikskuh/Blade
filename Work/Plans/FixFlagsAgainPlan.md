## Plan: Explicit ASM Flag Bindings

Replace the current implicit-only ASM flag model with explicit virtual flag inputs/outputs on ASMIR instructions, then add a dedicated flag-resolution pass before layout planning. The root cause is that /home/felix/projects/nerdgruppe/blade/Blade/IR/Asm/AsmLowerer.cs forces logical flag values through EmitCurrentLogicalFlagValue because /home/felix/projects/nerdgruppe/blade/Blade/IR/Asm/AsmModel.cs only exposes Condition and FlagEffect as implicit hardware state, with no place to bind a compare/test result to a virtual flag or to consume one later. The recommended approach is to make flag dataflow first-class in ASMIR, keep P2FlagEffect for concrete instruction semantics, and legalize virtual flag bindings to real C/Z state only when needed.

**Decisions**
- Included scope: internal ASMIR model, lowering, a dedicated flag-resolution pass, writers, analyses, and regression coverage.
- Excluded scope: typed inline asm syntax and parser changes for explicit flag input/output bindings. The user chose internal ASMIR first, so Docs/reference.blade, parser grammar, and VSCode syntax updates are deliberately out of scope for this change.
- Do not add compatibility shims that preserve the current implicit materialization path. The repo’s refactoring policy explicitly prefers deleting the wrong abstraction and fixing callers.
- Keep P2FlagEffect and P2ConditionCode as concrete instruction metadata, but add a local abstraction for per-slot C/Z reads and writes rather than trying to encode SSA dataflow solely inside those enums.
- The final assembly writer should remain concrete-only. Any unresolved virtual flag binding reaching that stage is a pipeline bug and should assert, not silently degrade.

**Further Considerations**
1. Prefer a dedicated new pass over folding this work into RegisterAllocator or AsmLegalizer. Flag lifetime resolution is semantically different from general register placement, and putting it before layout planning keeps code size accounting honest.
2. When introducing per-slot helpers, handle composite predicates like IF_C_AND_Z and IF_C_EQ_Z from the start even if the first implementation slice only needs IF_Z and IF_C. That avoids baking another partial flag model into the helpers.
